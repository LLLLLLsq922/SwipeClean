## 2. 背景与目标

### 2.1 现有体系的问题

M1 的六类污渍（`StainCategory`：Dust、FingerprintOil、Mud、Water、Sugar、Sand）解决了"工具—类别"二元匹配，但存在三个结构性缺口：

1. **颗粒度不足**：硬水水垢、指甲油、口香糖残胶全部落在"灰尘/糖渍"等类别内，玩家感受与处理手法差异巨大，却共享同一条效果规则；策划无法在不改代码的前提下做差异化关卡。
2. **无法表达相态**：现有模型只有"湿度 0..1"一个标量，无法表达"同一物质的干膜与湿态是两种不同物质"这一核心直觉。干茶渍与茶水在现有体系里是同一条规则，而玩家预期是"先喷湿软化再擦"与"直接吸干"两条完全不同的链路。
3. **物质库不可扩展**：新增物质需要判断是否新增 `StainCategory`，而枚举属于程序语义，改枚举等于改代码，与§5.3"内容 ID 不用枚举，避免新增普通内容必须改代码"的既定决策冲突。

### 2.2 本次需求要达成的目标

| 目标 | 说明 |
|---|---|
| G1 建立双相态顶层分类 | 引入 `StainPhase`（Dry/Wet）与 `StainSubtype`（14 个子类），每个子类以 `LegacyCategory` 回退映射到现有六类，保证 6 类 × 5 基础工具 = 30 个既有组合零改动仍有效 |
| G2 让相变成为玩法特色 | Dry→Wet（喷湿软化）与 Wet→Dry（风干/烘干，重量下降但附着上升）双向可逆，且永不造成不可恢复失败（ADR-009） |
| G3 把物质库变成纯数据 | 64 种物质以数据表接入，策划可独立增删；新物质接入的代码改动次数为 0 |
| G4 保持既有交付不倒退 | 既有 E04 系列 P0 验收项、§8.2 六类默认规则、§7.2 四通道语义、§2.3 画质档位全部继续成立 |

### 2.3 成功标准（可量化）

| 编号 | 指标 | 建议目标 | 测量方式 | 判定窗口 |
|---|---|---|---|---|
| S1 | "该喷湿再擦"直觉正确率 | ≥ 70% 首次尝试正确（区间 65%~80%）；教学关后 ≥ 85% | 埋点：干膜类污渍首次交互工具类别 == 推荐链首工具的比例；样本 ≥ 200 次交互/关 | M3 首轮内测 |
| S2 | 错误工具使用率下降 | 相对 M1 基线下降 ≥ 30%（区间 25%~40%） | 埋点：`WrongToolHintCooldown=2s` 去抖后的错误工具事件数 / 每关有效操作时长 | M3 与 M2 对比 |
| S3 | 单关平均有效操作时长 | 简单关 25~60 秒；中关 60~120 秒；难关 120~210 秒 | LevelSession 指标聚合（§10.5 既有聚合口径） | M2/M3 全量关卡 |
| S4 | 相变可感知率 | ≥ 75% 玩家在访谈中能描述"变少但变难擦" | 内测后 5 分钟结构化访谈，样本 ≥ 20 人 | M3 |
| S5 | 相变相关不可恢复失败 | 0 例 | 自动化 + 手工检查：任意相变序列后仍可达到完成阈值 | 每次构建 |

数值给出区间而非单点，原因是 M1 真机 30/60 FPS 基准尚未回填（详见《污渍系统可行性分析文档》§5）。

## 3. 术语表

| 术语 | 英文/代码 | 定义 |
|---|---|---|
| 相态 | `StainPhase` | 顶层分类，`Dry`（干物质）/`Wet`（湿物质）。表达"当前是干膜还是湿态"的玩法语义 |
| 干物质 | Dry | 以固体膜、颗粒、结晶或干胶形式存在的污渍；多数需要先复湿软化或先做机械移除 |
| 湿物质 | Wet | 以液体、糊状或胶体形式存在的污渍；核心矛盾是控流、吸收与黏着 |
| 子类 | `StainSubtype` | 二级分类，共 14 个（8 干 + 6 湿），是效果矩阵查找的主键之一 |
| 回退类 | `LegacyCategory` | 子类映射到的既有 `StainCategory`；效果矩阵在第一级查找失败时用它回退，保证 30 个既有组合继续有效 |
| 相变 | Phase Transition | `Dry↔Wet` 的状态迁移；由喷湿/自然蒸发/风干触发，双向可逆 |
| 软化进度 | `SofteningProgress01` | 既有运行时字段（§8.1）；湿度超过阈值时上升，低于阈值时回落（§8.3） |
| 控流 | Flow Control | 湿物质不越过笔画前方限定范围的能力；由吸收、黏度与工具压力共同约束 |
| 吸收 | Absorb | 吸水纸类工具按容量上限移除液态质量的机制；容量耗尽后效率线性下降 |
| 涂抹 | Smear | 错误工具导致的视觉面积扩大与峰值下降，R 总量近似守恒（§8.4） |
| 水痕 | `WaterMark` | 湿物质被布拖动后残留的副作用层，新增有效质量默认 5%、上限 10%（§8.4） |
| 流挂 | Sag / Run Down | 过度喷湿后湿膜在斜面或边缘产生的定向位移，属于可恢复副作用 |
| 划痕风险 | `ScratchRisk` | 硬颗粒被布拖动时产生的风险统计与短视觉痕迹，不进入永久存档（§8.5） |
| 二次污染 | Cross Contamination | 被工具带走的污渍转移到未污染区域，受污染半径与饱和度约束 |
| 复湿 | Re-wetting | 干膜吸收水分后相态转为 Wet 的过程，属于 Dry→Wet 相变 |
| 风干 | Air Dry | 湿膜失水转为干膜的过程，属于 Wet→Dry 相变；重量下降但附着上升 |
| 速干窗口 | Cure Window | 速干胶类物质的可用时间窗，窗口内可溶解，窗口后可清除但耗时显著增加 |

## 4. 范围

### 4.1 In Scope

1. `StainPhase`、`StainSubtype` 两个新枚举与 `StainDefinition` 的 `Phase`、`Subtype` 字段扩展。
2. 64 种物质的数据定义（ID、中文名、相态、子类、回退类、8 个 01 参数、溶剂标签、目标权重、难度）。
3. 效果矩阵四级查找链：`(Tool, Subtype+Tag) → (Tool, LegacyCategory, Tag) → (Tool, LegacyCategory) → (Tool, Phase 默认)`。
4. 双向相变的触发条件、状态表达与边界保护。
5. 副作用与风险：涂抹、水痕、流挂、划痕风险、二次污染。
6. 表现与反馈：分相态的视觉、音频、触觉、粒子与 HUD 提示。
7. 关卡与难度：子类配比、难度曲线、相变教学关。
8. 存档与埋点、兼容与迁移、性能与内存预算。

### 4.2 Out of Scope

| 排除项 | 理由 |
|---|---|
| 真实流体求解（Navier–Stokes、SPH、LBM） | ADR-004 已冻结：液体是规则驱动的近似表现（湿度、低分辨率位移、粒子）；GPU 预算无法容纳（详见《污渍系统可行性分析文档》§3） |
| 永久屏幕/设备损坏 | ADR-009：普通与放松模式的错误工具始终可恢复；商店与页面不得描述为真实损坏（§8.5） |
| 无限污渍生成 | 副作用新增质量必须有上限（水痕 5% 默认、10% 上限，§8.4） |
| 硬性失败与失败结算 | 相变与错误工具不得导致关卡不可完成；只允许影响评分与时长 |
| 联网、排行榜、云存档、第三方分析 SDK | §2.4 包与依赖政策明令禁止 |
| 新增需要审批的重量级包 | 相变只需在既有 Shader/RT 框架内扩展；如需新包必须走§2.4 审批流程 |
| 物质的自定义着色器逐物质分支 | 表现必须走 `VisualProfileId` 资产化，禁止按 ID 写分支 |

## 5. 干物质（Dry）需求

干物质共 9 个子类、36 种物质（本文档第 2.3 节表格编号 1~36）。通用系统行为适用于全部 36 种，物质条目只登记差异点。

### 5.1 干物质共性系统行为

| 行为 | 要求 |
|---|---|
| 默认相态 | `Phase=Dry`；初始 `DefaultMoisture01` 多为 0.00（编号 9~13 的结晶类为 0.05~0.20，编号 33 为 0.15） |
| 直接干擦 | 允许但按子类给出不同惩罚：松散颗粒类以"扬尘/推动"表现，膜类以"低效 + 涂抹"表现 |
| 复湿收益 | 喷湿使 `G` 上升，越过软化阈值后 `SofteningProgress01` 上升，布类效率显著提升（§8.3 口径不变） |
| 过度喷湿 | 在斜面/边缘关卡或长时间静置后允许出现流挂；流挂为可恢复副作用 |
| 风干影响 | 干膜再失水不产生新惩罚（已干），但反复复湿—风干循环必须收敛，不得累积不可清除残差 |
| 硬颗粒共性 | `Subtype=LoosePowder` 且 `Adhesion01 ≤ 0.10` 的物质（编号 2）与其他物质叠放时，布不得穿透下层（沿用§8.5） |
| 溶剂要求 | `RequiredSolventTag` 非空的物质，未满足标签的工具效率不得超过 `BaseEfficiency × 0.25` |

### 5.2 九个干子类分析

| 子类 | 数量 | 形成原因 | 玩家直觉预期 | 正确处理链 | 错误路径 | 必须满足的系统行为 |
|---|---:|---|---|---|---|---|
| LoosePowder | 8 | 干燥颗粒沉降或撒落 | "吹掉/扫掉，别用手抹" | 气吹 → 软刷；干布轻扫收尾 | 喷雾使其变湿成泥条；干布重压推动扩大范围 | 颗粒可被 Push 位移；湿化后 `SmearFactor01` 生效并提高附着 |
| SaltCrystal | 5 | 水蒸发后盐类结晶成膜 | "这是水干后的印子，普通擦不掉" | 酸性溶剂（若有）→ 复湿等待 → 湿布 | 直接干擦无效；用湿布环绕扩大环状印 | 结晶膜必须表现为"薄、透明、有边界"；必须响应 `RequiredSolventTag` |
| SugarFilm | 7 | 含糖液体干燥成膜 | "黏，得先泡软" | 喷雾 → 等待 → 湿布 | 过早擦拭低效、拉丝、B 通道上升 | 软化时间显著长于油膜；附着 ≥ 0.65 时布类未软化效率 ≤ 30% |
| OilFilm | 7 | 油脂铺展后凝固或半凝固 | "油，要用去油的" | 去油剂/喷雾 → 湿布 | 干布低效并 Smear | `SmearFactor01 ≥ 0.55` 时必须产生可观测的视觉位移 |
| ProteinFilm | 6 | 蛋白质类干燥变性成膜 | "干上去了，越擦越花" | 酶解 → 复湿 → 湿布；胶类（31/32）先冷脆化再溶剂 | 干擦撕扯、涂抹；热水使蛋白变性更难清除 | 蛋白类必须对温度或酶类标签有区分响应 |
| InorganicScale | 0（预留） | 无机盐/颜料类硬垢 | "硬，得用酸性" | 酸性溶剂 → 复湿 → 软刷 | 硬擦产生划痕风险 | 子类规则必须存在，即使 M2 无内容引用；M3 复用 |
| InkPigment | 3 | 颜料渗透或结膜 | "颜料，得用酒精/丙酮" | 溶剂 → 单向擦拭（由净向脏） | 湿擦向四周扩散色斑；反复往复涂抹 | 必须支持"单向擦拭效率高于往复"的规则开关 |
| AdhesiveResidue | 0（预留） | 胶体干燥残留 | "有胶，得用溶剂" | 溶剂 → 软化 → 布 | 干擦拉扯、残留不清 | 规则必须存在；与 ProteinFilm 的胶类条目共用溶剂标签；M3 复用 |

### 5.3 干物质工具—子类耦合矩阵

矩阵给出每个干子类的首推工具与禁止工具，是 HUD 提示（REQ-STAIN-062）与错误判定（REQ-STAIN-049）的数据来源。效率档含义：◎ 高（≥ 1.5×基础）、○ 中（0.8~1.5×）、△ 低（0.25~0.8×）、✕ 禁用（≤ 0.25× 且产生副作用）。

| 干子类 | 清洁布（干） | 清洁布（湿） | 喷雾 | 吸水纸 | 软刷 | 气吹 | UV 检查 | 溶剂类 |
|---|---|---|---|---|---|---|---|---|
| LoosePowder | ○ | △ | ✕ | ✕ | ◎ | ◎ | — | — |
| SaltCrystal | ✕ | ○（复湿后 ◎） | ○ | ✕ | ○ | △ | — | 有 acid 标签时 ◎ |
| SugarFilm | ✕ | ◎（软化后） | ◎ | ✕ | △ | ✕ | — | enzyme 可缩短软化 |
| OilFilm | ✕ | ◎（复湿后） | ○ | △ | ✕ | ✕ | — | degreaser 提升至 ◎ |
| ProteinFilm | ✕ | ○（酶解后 ◎） | ○ | ✕ | △ | ✕ | — | enzyme / solvent / acetone 按物质 |
| InorganicScale | ✕ | ○ | ○ | ✕ | ○ | △ | — | acid 必需 |
| InkPigment | ✕ | ✕ | ✕ | ✕ | △ | ✕ | — | alcohol / acetone 必需，且需单向擦拭 |
| AdhesiveResidue | ✕ | △ | ✕ | ✕ | △ | ✕ | — | solvent 必需 |
| 通用规则 | 干布对颗粒类为 ○，对膜类为 ✕ | 湿布只在软化/酶解完成后进入 ◎ | 喷雾对颗粒类是惩罚路径 | 吸水纸只对 Wet 相有效 | 软刷对颗粒类兼具推动与移除 | 气吹对 Wet 相效率下降 ≥ 50% | UV 不改变效率 | 无标签时必须落入 △ 或 ✕ |

矩阵与既有 30 个组合（§8.2）的一致性要求：六类回退行必须与§8.2 表格逐格一致，出现冲突时以§8.2 为准并修正本矩阵（REQ-STAIN-005 验收）。

| # | ID | 中文名 | 子类 | 独特玩法点 | 正确链 | 错误路径 | 必须满足的系统行为 |

## 6. 湿物质（Wet）需求

湿物质共 10 个子类、28 种物质（编号 37~64）。湿物质的核心矛盾是控流、吸收饱和、涂抹扩散、黏着拉丝与速干时间窗。

### 6.1 湿物质共性系统行为

| 行为 | 要求 |
|---|---|
| 默认相态 | `Phase=Wet`；`DefaultMoisture01` 普遍为 0.40~1.00（油性液体 45/46 为 0.10~0.50） |
| 控流 | 湿物质在笔画前方不得越过"工具半径 + 黏度修正"的边界；低黏度液体允许更低阻力的位移 |
| 吸收饱和 | 吸水纸按 `AbsorptionCapacity` 移除液态质量；容量耗尽后效率线性降至 0，HUD 需给出可感知反馈 |
| 涂抹扩散 | 布类错误使用时 R 总量近似守恒、峰值下降、面积扩大（§8.4） |
| 黏着拉丝 | `Viscosity01 ≥ 0.75` 时必须产生视觉拉丝与粘连音；拉丝期间工具效率下降 |
| 速干窗口 | `Subtype=FastCureAdhesive` 必须存在时间窗；窗口内溶剂效率高，窗口后效率显著下降但不得不可清除 |
| 风干 | 湿物质在静置或风干工具作用下转为干膜：重量下降、附着上升；双向可逆 |
| 遮盖与阻挡 | 高厚度湿物质（`DefaultThickness01 ≥ 0.45`）遮挡下层，需先移除或推动 |

### 6.2 十个湿子类分析

## 7. 相变机制需求

### 7.1 Dry → Wet（复湿与软化）

| 项 | 规定 |
|---|---|
| 触发条件 | 局部 `G` 上升越过 `SofteningMoistureThreshold01`（按子类配置：结晶类 0.30~0.40，糖膜类 0.40~0.55，油膜类 0.35~0.50，颗粒类 0.45~0.60，建议区间，理由是高附着膜需要更多水分才能破坏分子间结合） |
| 软化推进 | 沿用§8.3 公式（`softening += dt / softenDuration`），`softenDuration` 建议 1.5~4.0 秒；结晶类取短端，糖膜与胶类取长端 |
| 相变写入 | 局部 `Phase01` 由 Dry 向 Wet 平滑迁移，迁移不得阶跃；不改变 R 通道质量语义 |
| 相变后收益 | 布类效率提升建议 2~4 倍；气吹效率下降（湿颗粒更难吹动） |
| 过度喷湿 | 在斜面/边缘关卡或静置 ≥ 3 秒后允许流挂：沿重力方向产生定向位移，`A` 或扩展通道记录流挂强度 |
| 流挂边界 | 单次流挂造成的面积扩大 ≤ 20%，单关触发次数建议 ≤ 3 次，且不新增不可清除质量 |
| 禁止项 | 复湿不得使关卡不可完成；复湿不得生成新污渍层；复湿不得突破§7.2 活跃层上限 |

### 7.2 Wet → Dry（风干与烘干）

| 项 | 规定 |
|---|---|
| 自然风干 | `G` 按 `evaporationRate`（建议 0.02~0.08 /秒，油性取低端、水性取高端）自然衰减；`G` 低于 `dryPhaseThreshold01`（建议 0.15~0.25）时相态转 Dry |
| 主动烘干 | 新增"暖风"能力；`Wet→Dry` 速率建议为自然风干的 3~6 倍，但不得瞬时固化 |
| 质量变化 | 风干使厚度按比例下降（建议保留 40%~70% 的原始 `DefaultThickness01`），同时 `Adhesion01` 提升（建议 +0.10~0.25，上限 clamp 到 1.0） |
| 玩法语义 | 必须可被玩家感知为"变少但变难擦"：视觉上面积/厚度减小，操作上所需时长增加 |
| 反向可逆 | 已风干的膜再次喷湿必须能回到 Wet，且效率提升可量化；不得出现"永久固化"状态 |
| 与软化关系 | 相变到 Dry 时 `SofteningProgress01` 应快速回落（沿用§8.3 的 `dryBackDuration` 语义），避免干膜仍保留高软化值 |
| 与溶解关系 | 若物质已被部分溶解（R 下降），风干只影响剩余部分，不恢复已清除质量 |
| 禁止项 | 风干不得生成无法清除的层；不得使完成阈值不可达；不得在暂停时推进（§3.8 时间语义） |

### 7.3 相态状态表达

| 载体 | 表达要求 |
|---|---|
| 状态纹理 G | 沿用§7.2 语义：局部湿度 0..1，是相变的主驱动通道 |
| `Phase01` | 建议新增独立通道或由 `G` 与局部硬度推导；若新增通道需 RT 格式升级（详见《污渍系统设计文档》§4、§6；技术风险见《污渍系统可行性分析文档》§3） |
| 视觉 | 干膜：哑光、边缘锐利、有粉感；湿膜：高光、边缘柔、有流动感；过渡态必须存在中间表现，不得二值跳变 |
| 音频 | 干态为摩擦/颗粒音，湿态为粘连/液体音；相变瞬间允许一次短过渡音，不做循环切换 |
| HUD | 相变建议提示必须来自 `HintKey`，例如"先喷湿软化再擦"，不得在代码拼接物质名（§8.4、§11.8） |
| 降低动态效果 | 关闭流动位移与泡沫动画后，仍必须通过颜色/光泽/静态形状区分 Dry/Wet 与软化进度（§11.9） |

### 7.4 是否需要新工具

| 方案 | 描述 | 建议 |
|---|---|---|
| A. 新增 `AirDryer` 工具类别 | 新增 `ToolCategory` 枚举值 | 不推荐：会扩展效果矩阵列数并触碰§5.5 工具定义与既有 30 组合基线 |
| B. 气吹双模式 | 在 `ToolDefinition` 增加 `AirMode { Blow, Warm }`，暖风模式输出 `MoistureDeltaPerSecond < 0` | 推荐：复用已验证的输入与手感，改动面最小；能量/冷却作为平衡旋钮 |
| C. 纯自然风干 | 不加交互，仅时间驱动 | 作为兜底保留：保证关闭暖风时相变仍可发生，不影响可完成性 |

推荐 B + C 并存：暖风是"主动加速手段"，自然风干是"保底机制"，两者都必须走同一套相变规则与校验。
