# SwipeClean 清洁用品系统需求文档

> 摘要：本文档把 SwipeClean 的工具体系从"7 个工具类别"扩展为"12 个工具类别 + 10 种擦拭材质 + 5 种吸收耗材 + 4 种刷头 + 5 种机械头 + 9 档喷雾 + 3 种非喷雾助剂"的参数化体系，在既有 `ToolDefinition` / `ToolStainEffectRule` 字段与 ADR-006 / ADR-009 冻结裁决之上只做追加与参数化，并以 108 条可追溯编号需求（`REQ-TOOL-001~108`）与 31 条非功能需求约束 M2/M3/M4 的实现与验收。
>
> 口径说明（v1.1 勘误）：① 机械头为 **5 种**（`roller_adhesive`、`blade_plastic`、`blade_metal`、`eraser_rubber`、`steam_head`），枚举名 `MechanicHead`，跨 `AdhesiveRoller`/`Squeegee`×2/`Eraser`/`Steam` 四个类别；② 本文 §5.2 / §6.1~§6.3 的参数表为**领域参数口径**（吸液/吸油/掉毛/碎屑/耐擦/摩擦/抛光/静电/反渗/携载），与《清洁用品设计文档》的 `ToolDefinition` 字段（`RadiusUv`/`BaseEfficiency`/`AbsorptionCapacity`/`MoistureOutputPerSecond`/`PushStrength`/`ScratchRisk01`/`MaxPressureHoldSeconds`）**语义不同、互为补充**；需要同时使用两套数值时，以本文的领域参数解释"材质像什么"、以《清洁用品设计文档》§5.0 的数值解释"算法怎么算"，二者的字段映射见该文档的 `ToolSubtypeDefaults` 与用品卡"核心参数"条目。

## 2. 背景与目标

### 2.1 现有体系的问题

M1 已落地 `ToolCategory` 的 7 个成员（`Cloth`/`Spray`/`AbsorbentPaper`/`SoftBrush`/`AirBlower`/`UvInspector`/`AirDryer`），且 `ToolDefinition`、`ToolStainEffectRule`、`IToolStrategy`、`ToolRuntimeState` 的字段与接口已冻结（既有 spec §5.5、§5.6、§9.1、§9.2）。在这套体系之上，清洁用品侧存在三个结构性缺口：

1. **工具手感单一**：`Cloth` 是一套类（ADR-006），但"超细纤维布"与"棉布"、"纸巾"、"湿巾"在同一套 `ToolDefinition` 参数下无法表达差异；玩家换了用品却感受不到变化，工具的"选择"退化为"换个图标"。
2. **材质无差异**：掉毛、碎屑、释液反渗、一次性耗材、抛光能力、静电吸附这些"用品的物理人格"在现有 13 个字段中无处安放，导致"随手拿什么都能擦干净"，与解压游戏"讲究地用对工具"的核心快感冲突。
3. **辅助用品无体系**：吸收耗材（厨房纸/吸油纸/硅胶吸水片）、刷头（软毛/硬毛/静电/缝隙）、机械头（刮刀/橡皮擦/粘毛滚轮）、喷雾档位与助剂（软化剂/抛光蜡/防静电）目前既没有统一的分类口径，也没有统一的"错用后果"约束，内容侧无法在不改代码的前提下扩充（与《污渍系统需求文档》§2.1 第 3 点的"内容不因新增而改代码"原则同源）。

### 2.2 本次需求要达成的目标

| 目标 | 说明 |
|---|---|
| G1 类别扩到 12 值且只增不改 | 末端追加 `Sponge`/`Squeegee`/`Eraser`/`AdhesiveRoller`/`Steam` 五个成员，既有 7 个成员一个不删、一个不改名（`REQ-STAIN-077`、`REQ-TOOL-003`） |
| G2 把"用品差异"变成纯参数 | 擦拭材质 10 种落在 `Cloth` 内部；吸收耗材 5 种落在 `AbsorbentPaper`；刷头 4 种落在 `SoftBrush`；机械头 5 种落在 `Squeegee`/`Eraser`/`AdhesiveRoller`/`Steam`；喷雾 9 档落在 `Spray` 的 `SprayMode`；新增用品 = 新增一行数据，代码改动 0 |
| G3 让"错用"有代价但不失败 | 掉毛、碎屑、反渗、二次污染、划痕风险全部只影响效率与表现，永不产生不可清除状态、永不阻止完成（ADR-009、`REQ-TOOL-049`） |
| G4 保持既有交付不倒退 | 既有 30 组 `(6 类污渍 × 5 基础工具)` 基线与六类默认规则（既有 spec §8.2）逐格不变；既有 19 项 EditMode 与 2 项 PlayMode 测试不回归 |
| G5 状态与切换不破坏手感闭环 | 干/湿/饱和仍是 `Cloth` 的运行时状态（ADR-006）；切换耗时 ≤100ms（既有 spec §9.1）；饱和恢复仍旧免费无限（既有裁决） |

### 2.3 成功标准（可量化）

| 编号 | 指标 | 建议目标 | 测量方式 | 判定窗口 |
|---|---|---|---|---|
| S1 | 工具选择正确率 | 首次交互工具类别 == 推荐链首工具的比例 ≥ 70%（区间 65%~80%）；教学关后 ≥ 85% | 埋点 `tool_selected` 与关卡 `RecommendedSequence` 比对；每关样本 ≥ 200 次交互 | M3 首轮内测 |
| S2 | 每关有效工具切换次数 | 简单关 1~3 次；中关 3~6 次；难关 6~10 次（区间理由：低于 1 次说明工具无差异，高于 10 次说明步骤过碎） | `LevelSession` 聚合 `tool_switch_count / level_duration` | M3 全量关卡 |
| S3 | 材质误用率下降 | 相对"材质不可选"基线下降 ≥ 25%（区间 20%~35%） | 埋点：`wrong_tool_used` 中 `materialId` 维度的错误事件数 / 每关有效操作时长 | M3 与 M2 对比 |

| 饱和 | `Saturation01` | 工具已吸收量与容量的比值（既有 spec §9.2）；`Cloth`/`AbsorbentPaper` 有效，饱和后效率下降但不归零 |
| 拧干 | Wring | `Cloth` 的免费恢复动作：`Saturation01=0`、`Moisture01=0.35`，动作时长 ≤0.4s，无金币/广告/冷却（既有裁决） |

| 粘性衰减 | Tack Decay | `AdhesiveRoller` 的粘附能力随吸附次数下降；衰减到阈值后免费换纸（等价于拧干规则） |
| 推水 | Squeegee Push | `Squeegee` 沿运动方向成片推动液体/泥浆的操作，属于 `Push` 的定向高流量变体 |
| 软化剂 | Softener | 非喷雾助剂之一：降低附着、缩短软化时长；走独立 `AuxFormula` 槽或复用 `SprayMode`（方案对比见 §6.5） |
| 助剂 | `AuxFormula` | 非喷雾形态的辅助配方（软化剂、抛光蜡、防静电喷雾）的统一抽象 |

| 一次性耗材 | Consumable | 纸巾、擦镜纸、湿巾、面巾纸等不可复用的材质；破碎/饱和后的恢复动作是"更换"而非"拧干" |
| 免费恢复 | Free Recovery | 饱和/衰减/破碎后的恢复动作不消耗金币、不看广告、每关不限次数（既有裁决，本文档 `REQ-TOOL-045`） |

## 4. 范围

### 4.1 In Scope

1. `ToolCategory` 从 7 值扩到 12 值（末尾追加，不删不改名）与新增成员的合法性论证。
2. `ClothMaterial`（10）、`AbsorbentMaterial`（5）、`BrushHead`（4）、`MechanicHead`（5）、`SprayMode`（9）、`AuxFormula`（3）的参数域、语义与校验规则。
3. 每类用品的逐条需求：物理特性、玩家直觉预期、正确处理场景、错误使用后果、必须满足的系统行为。
4. 工具切换流程、切换耗时、竖屏工具栏交互、误触保护、状态保留/重置规则、单手可达性与 Safe Area。
5. 副作用与风险体系：划痕、掉毛、碎屑、反渗、二次污染、粘性衰减。
6. 表现与反馈：视觉、音频、触觉、HUD 提示与本地化键规范。
7. 关卡投放、解锁顺序与升级曲线的建议（M3+）。
8. 兼容与迁移：既有 30 组合基线不变、枚举只增不改、存档向前兼容。
9. 性能、内存、可维护性、可访问性与输入设备的非功能要求。

### 4.2 Out of Scope

| 排除项 | 理由 |
|---|---|
| 真实流体求解（Navier–Stokes、SPH、LBM） | ADR-004 与《污渍系统需求文档》§4.2 已冻结：液体是规则驱动的近似表现 |
| 永久屏幕/设备损坏 | ADR-009：错误工具始终可恢复；商店与页面不得描述为真实损坏 |
| 购买、货币化、真实容量与补给经济 | 本版本全部用品免费无限（`REQ-TOOL-044`）；`ToolUpgradeCurve` 的货币字段在 M2 不实现数值 |
| 无限污渍生成 | 副作用新增质量必须有上限（水痕 5%/10%、二次污染 ≤5%），与《污渍系统需求文档》§8.5 一致 |
| 联网、排行榜、云存档、第三方分析 SDK | 既有 spec §2.4 包与依赖政策明令禁止 |
| 每材质独立 Shader 或逐 ID 分支 | 表现必须走 `VisualProfileId` 资产化，禁止按 ID 写分支 |
| 真实材质缩略图/扫描贴图 | 授权链条与既有 spec §15.3 资产台账冲突；材质表现走程序化与图集复用 |
| 砂纸、刀片、化学危险品的拟真描写 | 与放松向定位冲突；"金属刮刀"只保留可恢复划痕风险与提示，不做破损描写 |

## 5. 擦拭材质需求（`Cloth` 参数化，10 种）

### 5.1 统一参数模型

`Cloth` 不新增 `ToolCategory` 成员（ADR-006 保持不变），而是在 `ToolDefinition` 之上追加一个 `ClothMaterialProfile` 数据记录（纯数据、可烘焙为整数键，详见《污渍系统设计文档》§4.6 的同类做法）：

```csharp
public sealed record ClothMaterialProfile(
    string Id,                      // ^cloth_[a-z0-9_]{2,63}$
    float Absorbency01,             // 吸液能力
    float OilPickup01,              // 吸油能力
    float LintShedding01,           // 掉毛倾向
    float DebrisRisk01,             // 碎屑/破碎风险
    float Durability01,             // 耐擦寿命
    bool  Reusable,                 // 是否可拧干复用
    float SqueezeRecovery01,        // 拧干后的恢复比例（0 = 不可复用）
    float SurfaceFriction01,        // 摩擦系数（影响抛光与划痕风险）
    float Polishing01,              // 抛光能力
    float StaticCharge01,           // 静电吸附（对干粉）
    float ReleaseBackRisk01,        // 释液反渗倾向
    float CarryLoad01)              // 溶剂/清水携载量
```

统一约束：全部 `01` 参数在 `[0,1]`；`Reusable=false` 的材质 `SqueezeRecovery01` 必须为 0；`LintShedding01 ≥ 0.60` 的材质必须配置 `hint_cloth_<id>_lint`；`DebrisRisk01 ≥ 0.60` 的材质必须走"更换"而非"拧干"。

### 5.3 逐材质需求

#### 5.3.1 `cloth_microfiber` 超细纤维布

- **物理特性**：涤纶/锦纶混纺超细旦纤维，`OilPickup01=0.95`（全场最高）、`LintShedding01=0.08`、`Absorbency01=0.70`、可水洗复用。
- **玩家直觉预期**："万能布"，拿来就能擦，不挑活。
- **正确处理场景**：`OilFilm`/`OilLiquid` 的收尾擦拭；`LowViscosityLiquid` 吸干后的水痕收尾；软刷/气吹后的最终抛光。
- **错误使用后果**：对抗 `InkPigment` 时仍受"往复擦扩散色斑"约束（《污渍系统需求文档》§5.3 的 ✕ 档不改）；对 `LoosePowder` 干擦会把细粉推入纹理，效率按 `SmearFactor01` 反向衰减。
- **必须满足的系统行为**：`REQ-TOOL-020`、`REQ-TOOL-021`；首次进入游戏时必须是默认 `ClothMaterial`，且不允许任何关卡把它设为不可用，以保证"总能擦干净"的保底路径存在。

#### 5.3.2 `cloth_nonwoven` 无纺布

- **物理特性**：一次性湿巾基材，`Absorbency01=0.80`、`LintShedding01=0.45`、`Durability01=0.40`、可复用但恢复率仅 0.35。
- **玩家直觉预期**："便宜的耗材，用几次就该换"。
- **正确处理场景**：中低难度 `ViscousPaste` 的第一遍"降低厚度"；`CompositeSludge` 降黏后的清理。
- **错误使用后果**：反复拧干后效率从 1.0 线性跌到 `0.35 → 0.60` 区间；掉毛在深色表面上形成可见纤维残留（表现为脏点，可清除、不入存档）。
- **必须满足的系统行为**：`REQ-TOOL-022`；`SqueezeRecovery01 < 0.50` 时 HUD 需要给出"建议更换"提示，提示键 `hint_cloth_nonwoven_replace`。

#### 5.3.3 `cloth_cotton` 棉/针织布

- **物理特性**：天然棉，`Absorbency01=0.90`（最高）、`OilPickup01=0.30`（偏低）、`LintShedding01=0.80`（高）。
- **玩家直觉预期**："吸水很强，但好像会留毛"。
- **正确处理场景**：`LowViscosityLiquid` 的大面积吸干与收尾；`stain_tea_wet`/`stain_juice_wet` 的色素液体擦除。
- **错误使用后果**：擦油类时效率被 `OilPickup01` 压低到基准的 0.55 倍左右，且必须在表面上留下可见纤维（掉毛表现）；`LintShedding01 ≥ 0.60` 时同一关卡累计掉毛超过阈值需触发一次提示。
- **必须满足的系统行为**：`REQ-TOOL-023`；掉毛必须计入 `lint_events` 埋点（`REQ-TOOL-064`），且掉毛残留的清除不需要专用工具（避免形成双重要求）。

#### 5.3.4 `cloth_paper_towel` 纸巾

- **物理特性**：木浆纤维，`DebrisRisk01=0.85`、`Durability01=0.20`、`Reusable=false`；遇水后强度进一步下降。
- **玩家直觉预期**："用一次就扔，脏活重活用它"。
- **正确处理场景**：`ViscousPaste`/`CompositeSludge` 的粗清理第一遍；高厚污渍的"先减量"。
- **错误使用后果**：湿擦超过 `WetBreakThresholdSeconds`（建议 1.5~3.0 秒）后破碎，当前笔画立即中断并产生纸屑残留（可清除、不入存档），HUD 提示更换。
- **必须满足的系统行为**：`REQ-TOOL-024`；破碎必须是**可中断且可恢复**的事件：破碎后 `Saturation01` 归零、`DebrisRisk01` 的残留由后续任意工具一次带走；不得出现"半张纸仍以 30% 效率继续工作"的中间态（避免状态不可读）。

#### 5.3.5 `cloth_cotton_pad` 化妆棉/棉片

- **物理特性**：压实棉，`RadiusUv` 建议 0.035~0.05（全场最小档）、`SurfaceFriction01=0.80`、`DebrisRisk01=0.45`、`Reusable=false`。
- **玩家直觉预期**："小面积精修，用力一点才有用"。
- **正确处理场景**：`InkPigment` 的单向精修（由净向脏）；`stain_fingerprint_oil` 一类边缘薄污的定点处理。
- **错误使用后果**：高摩擦在硬颗粒上把 `ScratchRisk` 统计提高 1.3 倍（相对 `cloth_microfiber` 基准）；小半径导致大面积污渍的操作时长显著上升。
- **必须满足的系统行为**：`REQ-TOOL-025`；小半径材质必须在 HUD 上显示真实作用范围（沿用既有 spec §9.6 的"视觉与实际偏差 ≤10%"要求）。

#### 5.3.6 `cloth_suede` 眼镜布/麂皮

- **物理特性**：超细纤维绒面，`Polishing01=0.90`（最高）、`LintShedding01=0.05`、`Absorbency01=0.30`、`ReleaseBackRisk01=0.05`。
- **玩家直觉预期**："只适合最后擦亮，不能拿来吸脏东西"。
- **正确处理场景**：完成前的抛光收尾（`REQ-TOOL-027`）；`stain_fingerprint_oil` 的薄层镜面恢复。
- **错误使用后果**：低吸液使其对液体污渍效率仅为基准的 0.35 倍左右；不带走液体时反复擦拭只推开水痕。
- **必须满足的系统行为**：`REQ-TOOL-026`；抛光必须只影响视觉参数（光泽/粗糙度），**不得写入 R 通道**（保持 R 为覆盖率真值，沿用《污渍系统设计文档》§7.2 的写入封闭性论证）。

#### 5.3.7 `cloth_sponge` 海绵（布类回退）

- **物理特性**：开孔聚氨酯，`Absorbency01=0.95`（最高）、`SqueezeRecovery01=0.95`、`ReleaseBackRisk01=0.80`（最高）。
- **玩家直觉预期**："能吸很多，但挤不干净会把水又抹回去"。
- **正确处理场景**：大面积液体的搬运（配合 `Squeegee` 推水后吸水）；需要反复挤干的高含水场景。
- **错误使用后果**：饱和后继续擦会产生反渗，把已吸走的液体重新释放，表现为水痕增长与效率反降；反渗总量受水痕上限约束（默认 5%、硬上限 10%）。
- **必须满足的系统行为**：`REQ-TOOL-028`、`REQ-TOOL-052`；反渗必须是**可感知的负反馈**（视觉上表面重新变亮/变湿 + 一次低频提示音），且拧干后立即消失。

#### 5.3.8 `cloth_lens_tissue` 擦镜纸

- **物理特性**：超薄木浆，`DebrisRisk01=0.95`（最高）、`Durability01=0.10`、`Absorbency01=0.45`、`ReleaseBackRisk01=0.60`。
- **玩家直觉预期**："很娇贵，只能轻轻擦一次"。
- **正确处理场景**：`InorganicScale` 预留类与镜头膜类的高精度抛光；极小面积的残痕收尾。
- **错误使用后果**：湿擦或高压下几乎立即破碎（`WetBreakThresholdSeconds` 建议 0.8~1.5 秒）；破碎产生的纸屑在表面留下白点。
- **必须满足的系统行为**：`REQ-TOOL-029`；破碎阈值必须比纸巾更严，且在 HUD 上用"脆弱度"图标提前告知（不得只在破碎后提示）。

#### 5.3.9 `cloth_static_dust` 静电除尘布

- **物理特性**：带电纤维，`StaticCharge01=0.95`（最高）、`Absorbency01=0.25`、`LintShedding01=0.30`。
- **玩家直觉预期**："专门吸灰的，不沾水"。
- **正确处理场景**：`LoosePowder` 的干粉收集（不飞散）；气吹前的预处理，减少二次污染。
- **错误使用后果**：任何湿用场景（`Moisture01 ≥ 0.30`）都会使 `StaticCharge01` 在线性时间内归零，退化为一块低效的普通布，并给出一次提示。
- **必须满足的系统行为**：`REQ-TOOL-030`；静电吸附必须降低 `LoosePowder` 的二次污染计数，而不是提高效率上限（保持"气吹/软刷仍是主链"的既有结论）。

#### 5.3.10 `cloth_wet_wipe` 一次性清洁湿巾

- **物理特性**：含清洁液无纺布，`CarryLoad01=0.95`（最高）、初始 `Moisture01` 建议 0.75、`Durability01=0.35`、`Reusable=false`。
- **玩家直觉预期**："自带清洁液，开袋就能用，但用一会儿就干了"。
- **正确处理场景**：`SugarFilm`/`OilFilm` 的软化前置与一次性清理；没有喷雾工具时的替代路径。
- **错误使用后果**：`CarryLoad01` 耗尽后（建议 6~12 秒连续使用）退化为干布，若继续用于需要溶剂的物质则按"无标签"降级处理（效率 ≤0.25 倍）。
- **必须满足的系统行为**：`REQ-TOOL-031`；湿巾自带液体必须换算为 `AddMoisture` 命令输出，**不得**绕过 `BrushCommand` 直接改湿度（保证 R/G 通道写入封闭性）。

- `REQ-TOOL-039`（硬毛刷）：`ScratchRisk01=0.45` 只允许产生"统计 + 短视觉痕迹 + 双击触觉"，痕迹不进入永久存档，且在后续正确擦拭或完成演出中消失（ADR-009）。
- `REQ-TOOL-040`（静电刷）：对干粉的二次污染比例必须比软毛刷低 ≥60%；对 `Wet` 相子类效率 ≤0.30×，且必须触发提示。
- `REQ-TOOL-041`（缝隙刷）：`RadiusUv ≤ 0.06`，必须与 `cloth_cotton_pad` 同级地显示真实作用范围；不得因小半径使单位时间效率低于配置下界 0.02/s（沿用既有 spec §9.5 的 `effectivePerSecond` 下界）。

### 6.3 机械头 5 种

| ID | 类别 | 中文名 | 主操作 | 关键参数 | 主要风险与恢复 |
|---|---|---|---|---|---|
| `roller_adhesive` | `AdhesiveRoller` | 粘毛滚轮 | `Clean`（接触吸附） | 初始粘性 1.0；每次吸附衰减 0.03~0.06；阈值 0.35 提示 | 粘性衰减 → 免费换纸（等价拧干规则） |
| `blade_plastic` | `Squeegee` | 塑料刮刀 | `Push` + `Clean`（卷屑） | `PushStrength` 0.55；硬壳效率 0.6 | 无划痕风险；对胶类低效 |
| `blade_metal` | `Squeegee` | 金属刮刀 | `Push` + `Clean`（铲硬壳） | `PushStrength` 0.70；`ScratchRisk01` 0.60 | 只产生可恢复划痕风险；对镀膜类必须提示 |
| `eraser_rubber` | `Eraser` | 橡皮擦 | `Clean`（摩擦剥离） | 干膜专用效率 0.9；湿污 ≤0.15 | 产生橡皮屑（可清除、不入存档） |

逐条需求：

- `REQ-TOOL-042`（粘毛滚轮）：对 `LoosePowder`（尤其毛发、纤维、线头类变体）必须是最高效路径（≥1.5×）；对 `Wet` 相一律 ≤0.25×；粘性衰减后效率线性下降，`tack ≤ 0.35` 时必须显示可点击的"换纸"入口，换纸免费且不限次数。
- `REQ-TOOL-043`（刮刀族）：塑料与金属的区别只允许体现在 `PushStrength`、硬壳效率与 `ScratchRisk01` 三项上；两者都必须支持"推水"（`Squeegee Push`）把液体整片推向吸水耗材的作用半径内。
- `REQ-TOOL-044`（金属刮刀）：`ScratchRisk01=0.60` 只产生风险统计 + 短视觉痕迹 + 双击触觉；在镀膜类/金属件类物质上必须给出一次 `hint_metal_blade_coating` 提示；不得产生永久存档标记、不得降低完成上限（ADR-009）。
- `REQ-TOOL-045`（橡皮擦）：只对"低附着干膜"（`Adhesion01 ≤ 0.60` 且 `Phase = Dry` 的膜类）有高效；摩擦产屑必须可被任意后续工具一次带走；对湿污与胶类必须有明确低效提示。
- `REQ-TOOL-046`（蒸汽头）：输出湿度必须走 `AddMoisture` 命令（`MoistureDeltaPerSecond > 0`）；`heat` 标签只允许提高 `ProteinFilm` 的附着（负面）与加速 `SugarFilm` 软化（正面）；蒸汽不得改变 R 通道（沿用《污渍系统设计文档》§7.2 的写入封闭性）。
- `REQ-TOOL-047`（机械头与 R 真值）：全部机械头的写入只允许是 `Clean`（减法、下限 0）、`Push`（采样位移）与 `Smear`（权重和为 1 的卷积）三类线性算子，禁止任何"凭空加常量"的写入（`REQ-TOOL-047` 与《污渍系统设计文档》§7.2 的三条论证一致）。

### 6.4 喷雾 9 档（`SprayMode`）

在《污渍系统设计文档》§9.4 方案 A 的 7 档（`Water`/`Acid`/`Degreaser`/`Enzyme`/`Solvent`/`Alcohol`/`Acetone`）基础上扩到 9 档，末尾追加 `Isopropyl` 与 `Alkaline`：

| 档位 | 中文名 | 作用机制 | 溶剂标签 | 输出湿度（建议） | 风险与提示 |
|---|---|---|---:|---|---|
| `Water` | 纯水/蒸馏水 | 湿润、软化干膜、溶解糖盐 | —（无标签） | +0.70 | 过量致流挂（`REQ-STAIN-028` 口径） |
| `Alcohol` | 75% 酒精 | 快速挥发、溶解部分油墨 | `alcohol` | +0.45 | 挥发快、作用时间短（1.5~3.0 秒窗口） |
| `Isopropyl` | 异丙醇 99%（**新增**） | 电子件专用、低残留、低含水 | `alcohol` | +0.25 | 对某些涂层有风险提示；不得与 `Water` 同效 |
| `Acid` | 酸性清洁液（柠檬酸/醋） | 溶解水垢皂垢 | `acid` | +0.60 | 对金属件与镀膜有风险提示 |
| `Alkaline` | 碱性清洁液/肥皂水（**新增**） | 皂化油脂 | `alkaline` | +0.65 | 残留需二次清水擦拭 |
| `Degreaser` | 去油剂/表面活性剂 | 乳化油膜 | `degreaser` | +0.55 | 过量致打滑、需收尾 |
| `Enzyme` | 酶解清洁液 | 分解蛋白/胶质 | `enzyme` | +0.75 | 需等待反应时间 1~3 秒 |
| `Solvent` | 有机溶剂（除胶剂） | 溶胶、溶胀聚合物 | `solvent` | +0.40 | 高挥发、气味重 |
| `Acetone` | 丙酮/洗甲水 | 指甲油、速干胶 | `acetone` | +0.35 | 最高风险档，需保护涂层提示 |

**新增两档的理由**：

1. `Isopropyl`（异丙醇 99%）的理由是**把 `alcohol` 标签拆成"高含水短作用"与"低含水低残留"两种手感**。现有 75% 酒精档的 `MoistureDeltaPerSecond` 偏高，用于电子件类描述时与"低残留"直觉冲突；`Isopropyl` 用 +0.25 的极低含水输出给出"擦了就走、不留水痕"的差异，且不新增溶剂标签（仍复用 `alcohol`），因此不触碰 30 组合基线与 6 个标签的校验面。
2. `Alkaline`（碱性/肥皂水）的理由是**补齐"皂化"这一缺失的化学直觉**。现有 9 档中，油脂只由 `degreaser`（乳化）覆盖，但 `stain_soap_scum`（皂垢）与 `stain_sweat_salt`（汗渍盐霜）在物理上更接近"碱与皂的再乳化"，需要一条"先碱化再清水收尾"的路径；`Alkaline` 引入新的 `alkaline` 标签，代价是溶剂标签从 6 个扩到 7 个（见 `REQ-TOOL-050` 与第 12 章开放问题）。

逐条需求：

- `REQ-TOOL-048`（档位枚举完整性）：`SprayMode` 必须包含上表 9 个成员，命名与拼写逐字一致；EditMode 反射测试断言成员集合（`REQ-TOOL-002`）。
- `REQ-TOOL-049`（标签映射）：`Water` 与 `Alkaline` 之外的档位必须映射到《污渍系统设计文档》§4.5 的标签掩码；`Water` 的 `SolventTagSet` 必须为 `Empty`（`Mask = 0`，判定恒真）。
- `REQ-TOOL-050`（标签集合扩展）：若采用 `alkaline`，则 `SolventTagSet.Mask` 从 6 bit 扩为 7 bit，`REQ-STAIN-014` 的"每个非空标签至少有一个工具可提供"校验必须对 7 个标签全部重跑；该扩展必须在 MIG 组登记（`REQ-TOOL-085`）。
- `REQ-TOOL-051`（标签匹配语义）：匹配判定沿用 `(toolMask & stainRequiredMask) != 0`；命中时效率乘子 `1.0 + 0.35 × MatchStrength`，未命中时效率乘子收紧到 0.18~0.45 区间（沿用《污渍系统设计文档》§9.3 的收紧值），并必须触发 `HintKey` 提示。
- `REQ-TOOL-052`（错档降级）：任何"错档"必须满足三条：效率落入 ≤0.25× 档、给出一次限频提示（`WrongToolHintCooldown = 2s`）、**仍存在可完成路径**（切换到正确档位或改用机械手段）。禁止"错档后永远擦不掉"。
- `REQ-TOOL-053`（档位选择器交互）：9 档不得一次性全展开；竖屏下采用"3 主档 + 长按展开 6 进阶档"的两级结构，主档建议 `Water`/`Degreaser`/`Solvent`（覆盖最高频场景），进阶档按 `REQ-TOOL-054` 的顺序排列。
- `REQ-TOOL-054`（档位解锁顺序）：`Water` → `Degreaser` → `Solvent` → `Enzyme` → `Alcohol` → `Acid` → `Isopropyl` → `Alkaline` → `Acetone`（理由：先给"能解决大多数问题"的三档，把高认知负荷与高风险档位放到后期关卡，与《污渍系统需求文档》§10 的内容分批一致）。
- `REQ-TOOL-055`（档位切换状态）：切换档位属于 `ToolRuntimeState.SolventMode` 的变更，不重置 `Saturation01`；档位切换与工具切换同样受 ≤100ms 约束（`REQ-TOOL-058`）。
- `REQ-TOOL-056`（胶囊只做表现）：喷雾的"档位胶囊"只做表现层，不引入真实容量、不消耗、不可用尽（沿用《污渍系统设计文档》§9.4.3 的"唯一被接受的方案 B 元素"）。
- `REQ-TOOL-057`（档位与湿度的双通道输出）：每个档位必须同时定义 `SolventTag` 与 `MoistureDeltaPerSecond`；`Isopropyl` 与 `Solvent` 的低湿度输出不得被后续规则忽略（即"低含水档位"必须在 `MoistureModifier` 曲线上产生可测量的差异）。

### 6.5 非喷雾助剂 3 种：方案对比与推荐

三种非喷雾辅助配方：软化剂/表面活性剂（降低附着、加速软化）、抛光蜡/屏幕抛光剂（收尾恢复光泽）、防静电喷雾（预防吸尘）。

| 方案 | 描述 | 优点 | 缺点 | 对既有基线的影响 |
|---|---|---|---|---|
| **方案 A：并入 `SprayMode`** | 三种助剂各占一个 `SprayMode` 档位，喷雾档从 9 扩到 12 | 实现面最小：不新增类别、不新增字段、UI 复用同一个档位选择器；`IToolStrategy` 实现数 +0 | 语义混淆：软化剂不是溶剂、抛光蜡不是清洁液、防静电是"预处理"而非"处理"；12 档超出认知负荷；`SolventTag` 语义被污染（抛光蜡与防静电都不该参与溶剂匹配） | 不改 30 组合；但 `SprayMode` 语义从"溶剂档"变成"喷雾内容物"，与《污渍系统设计文档》§9.4 的"溶剂档位"命名冲突 |
| **方案 B：独立 `AuxFormula` 槽（推荐）** | 新增一个与 `Spray` 并列的"助剂槽"：`AuxFormula { Softener, PolishWax, AntiStatic }`，由 HUD 上的第二枚按钮（长按弹出三选一）承载，`ToolRuntimeState.AuxFormula` 记录当前助剂 | 语义干净：助剂不参与溶剂标签匹配（`SolventTagSet` 恒为 `Empty`）；可独立做"一次性/持续性"差异（软化剂按秒输出、抛光蜡按完成前可用、防静电按关卡一次性）；UI 上"清洁"与"护理"两枚按钮分工明确，符合解压游戏"做完还要擦亮"的节奏 | 新增一个 `ToolCategory` 成员（`AuxApplicator`）或一个并列表；HUD 需多占一枚按钮（建议放在工具栏右端或顶部，不挤压五工具命中区） | 只增不改：新增成员在末尾追加，30 组合不受影响；`AuxFormula` 的 `SolventTagSet` 恒空，因此不扩大标签校验面 |
| **方案 C：做成一次性道具（卡片/贴纸）** | 助剂作为可拖拽的一次性道具，使用后消失 | 表现力强、适合"惊喜时刻" | 引入"用完了怎么办"的可恢复性问题，与 ADR-009 有张力；与本版本"全部免费无限"的决策直接冲突 | 不推荐 |

**推荐方案 B**，理由按权重排序：

1. **语义正确性优先**：抛光与防静电在物理上不参与"溶解"，把它们塞进 `SprayMode` 会让 `REQ-TOOL-050` 的标签校验失去意义，并在后续新增物质时产生"抛光蜡能不能擦水垢"这类无意义规则。
2. **不触碰既有基线**：方案 B 的 `AuxFormula` 恒为 `SolventTagSet.Empty`，因此 30 组合与 6/7 个标签的校验面完全不变，符合 `REQ-STAIN-005` 的"迁移前后效率差异 ≤5%"。
3. **与"免费无限"一致**：方案 B 的助剂名额与饱和恢复同源——免费、不限次数，只是通过"是否已抛光""是否已防静电"的布尔状态提供阶段感，不引入经济系统（`REQ-TOOL-044`）。
4. **保留方案 A 的降级路径**：若 M4 之后产品认为"助剂槽"过重，把 `AuxFormula` 的三个成员并入 `SprayMode` 是"加枚举 + 加 3 条规则"的增量改动，不需要推翻数据结构。

逐条需求：

- `REQ-TOOL-059`（助剂槽字段）：`ToolRuntimeState` 追加 `AuxFormula`（枚举，默认 `None`）与 `AuxApplied01`（0~1，用于"已覆盖程度"的表现），既有字段全部保留（沿用《污渍系统设计文档》§9.2.1 的"只追加不改变"口径）。
- `REQ-TOOL-060`（软化剂）：必须在 1~3 秒内把目标物质的 `SoftenDuration` 缩短 ≥30%（区间 30%~50%），并在 HUD 上用"附着下降"图标表达；对已软化的物质重复使用只增加浪费提示，不叠加。
- `REQ-TOOL-061`（抛光蜡）：只允许影响 `VisualProfileId` 的光泽/粗糙度与"完成演出"表现，**不得写入任何状态纹理通道**；使用时不得提高 `Cleanliness01`（防止"抛一下就算擦干净"） 。
- `REQ-TOOL-062`（防静电喷雾）：作用是把后续 `LoosePowder` 的二次污染比例降低 ≥40%（区间 40%~60%），持续到本关结束或下一次湿用为止；不得提高移除尘效率（保持"气吹/软刷/静电布是主链"）。
- `REQ-TOOL-063`（助剂与标签隔离）：三种助剂的 `SolventTagSet` 必须恒为 `Empty`（`Mask = 0`），构建校验断言这一点，防止后续误加标签导致 `REQ-STAIN-014` 的"存在提供者"判定被放松。
- `REQ-TOOL-064`（助剂埋点）：三种助剂必须各自上报使用次数与使用时机（首帧/中段/收尾），字段与《污渍系统设计文档》§13 的事件字典口径一致。

## 7. 工具切换与操作需求

### 7.1 切换流程

沿用既有 spec §9.1 的六步顺序，且不允许插入任何可能阻塞的步骤：**取消旧笔画 → 停止旧循环反馈 → 保存旧工具会话状态 → 替换 Strategy → 刷新指针/HUD → 播放切换反馈**。完整过程目标 ≤100ms（沿用既有验收 `IT-007`）。

- `REQ-TOOL-065`（切换耗时）：从点击/滑选到"新工具可产生第一条有效命令"的耗时 P95 ≤100ms、中位数 ≤60ms；切换过程中已产生的笔画必须被正确取消（不得把旧工具的 `Clean` 命令以新工具参数发出）。
- `REQ-TOOL-066`（切换原子性）：切换必须是原子的：`ToolController` 在任一瞬间只持有一个 `IToolStrategy`；切换失败（资源未就绪）时必须回退到切换前状态，而不是进入"无工具"状态。
- `REQ-TOOL-067`（切换反馈）：切换必须同时给出视觉（工具栏选中轮廓 + 指针形状）、音频（`ToolSwitch` 语义短音）与触觉（一次轻触）；三者与 `FeedbackResolver` 的去抖规则一致，不得在快速连点下叠加播放。
- `REQ-TOOL-068`（快速连点保护）：同一工具在 300ms 内的重复点击视为一次；连点产生的切换必须合并，禁止排队执行多次完整切换流程（避免 100ms × N 的累积延迟）。

### 7.2 竖屏工具栏交互

- `REQ-TOOL-069`（工具栏布局）：底部工具栏承载"允许工具集"（既有 spec §11.4 的"最多五个基础工具"），新增类别不得突破该约束：5 个之后的类别必须走**分组入口**（例如"耗材"分组承载 `AbsorbentPaper` 的 5 种材质、"刷具"分组承载 `SoftBrush`/`Eraser`/`AdhesiveRoller`），UV 仍走侧边检查入口。
- `REQ-TOOL-070`（分组切换深度上限）：任意工具的选中路径深度 ≤2 层（点击 + 一次展开），理由是把"选工具"的认知成本压在 2 步内，避免 12 类 + 10 材质 + 9 档的笛卡尔积暴露给玩家。
- `REQ-TOOL-071`（误触保护）：工具栏热区必须与清洁表面保持 ≥24dp 的间距；工具栏区域内的 `PointerDown` 不得生成任何 `BrushCommand`（防止"选工具时擦到屏幕"）；工具按钮的最小热区为 48×48dp。
- `REQ-TOOL-072`（误触撤销窗口）：工具切换后 150ms 内允许"再次点击原工具"无损回退，回退不重置任何状态（不消耗、不计数、不提示错误）。
- `REQ-TOOL-073`（选中态多通道表达）：当前工具必须同时具备选中轮廓/形状、图标与可访问名称，不能只靠变色（沿用既有 spec §11.4 与无障碍要求）。

### 7.3 切换时的状态保留与重置

| 状态 | 切换工具时 | 切换材质（同类别内）时 | 切换档位（`Spray` 内）时 | 依据 |
|---|---|---|---|---|
| `Saturation01` | 按工具实例独立保存，切回时保留 | 保留（同一 `Cloth` 实例内材质切换视为"换布"，饱和归零） | 不适用 | 既有 spec §9.2；`REQ-TOOL-074` |

### 10.2 M2 必做与可延后的边界

| 归类 | 内容 | 理由 |
|---|---|---|
| M2 必做 | 12 值枚举的**定义**与合法性登记（`REQ-TOOL-001~009`）；3 种材质 + 2 种耗材 + 3 档喷雾的可玩闭环；切换与状态保留的全部 P0 条目 | 枚举与状态是数据结构，越晚定义迁移成本越高；材质与档位是"手感差异"的最小验证集 |
| M2 可延后 | 掉毛/碎屑的完整表现、粘性衰减、助剂、5 个新增类别的 `IToolStrategy` | 这些是"增量内容"，其数据结构在 M2 已就绪，延后不产生返工 |
| M3 必做 | 4 种刷头与塑料刮刀；6 档喷雾；副作用上限的全部 P0 验收 | 与《污渍系统需求文档》§10 的 M3 内容量（12 关）匹配 |
| M4 必做 | 5 个新增类别、`blade_metal`、9 档齐备、升级曲线 | 与软发布前的包体与内容量门禁匹配 |

### 10.3 排期风险与应对

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| 10 种材质的视觉资产产能不足 | 中 | 中 | 复用 3~4 个原型（绒面/针织/纸质/海绵），用材质属性与纹理平铺差分化；参见《污渍系统可行性分析文档》§4.2 的共用原型降本 |
| 9 档喷雾超出玩家认知负荷 | 中 | 高 | 强制两级选择器（`REQ-TOOL-053`）+ 分档解锁（`REQ-TOOL-054`）+ 先只做 3 档的 M2 验证（第 12 章开放问题 3） |
| 金属刮刀的风险表达被理解为"惩罚" | 中 | 中 | 痕迹不入存档、完成演出清除（`REQ-TOOL-096`）；商店与页面不得描写破损 |
| 材质差异不可辨识 | 中 | 中 | S6 盲测门禁；不达标时优先降级为"3 材质 + 其余作为皮肤" |
| 新增类别触碰 30 组合基线 | 低 | 高 | `REQ-TOOL-006/007` 的回归验收 + `ContentValidator` 的"12 类别 × 14 子类"全矩阵校验 |

|---:|---|---|---|---|
| 1 | 金属刮刀（`blade_metal`）是否进入首版 | 主策 | 不进 M2/M3，M4 与 `Squeegee` 类别一起上；若进，必须同时上线"痕迹不入存档 + 完成演出清除"两条验收 | 决定 `Squeegee` 类别的风险表达强度与用户测试中的"挫败"评分 |
